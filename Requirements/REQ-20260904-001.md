# REQ-20260904-001：首页 GIF 开场动画（第一屏全屏 + 播完才显示导航栏）

- **类型**：功能
- **工程**：根站（Eleventy）
- **状态**：已完成
- **创建日期**：2026-09-04
- **依据**：用户提供 `static/image/Animation/index/up.GIF`、`overlook.GIF`，要求首页第一块 section 全屏播放，导航栏等两张 GIF 播完后再显示

## 总目标

首页进入时，用两张既有 GIF 组成一段开场动画，占满第一屏；播放期间导航栏不出现，两张 GIF 依次播放完毕后导航栏淡入、页面恢复可滚动。

## GIF 素材实测参数（构建期解析 GIF 文件头得出）

| 文件 | 尺寸 | 帧数 | 单轮时长 | 循环 | 播放顺序 |
|---|---|---|---|---|---|
| `static/image/Animation/index/overlook.GIF` | 712×400 | 93 | 9.3s | 无限循环 | 第 1 段 |
| `static/image/Animation/index/up.GIF` | 712×400 | 85 | 8.5s | 无限循环 | 第 2 段 |

两张 GIF 均为无限循环，无「播放结束」事件可监听，因此时长以 `data-duration` 显式声明，由脚本计时切帧；提前 200ms 切帧以避开循环回跳。

## 实施方案

### 状态机（全部由 `<html>` 上的类驱动）

| 类 | 添加者 | 作用 |
|---|---|---|
| 无类 | — | 不播放开场动画，导航栏按原逻辑显示（无 JS / 降级） |
| `intro-gif-armed` | `<head>` 内同步脚本 | 锁定滚动；隐藏 `nav`、汉堡菜单、两条进度条、移动端菜单 |
| `intro-gif-running` | `index-intro-gif.js` | 真正显示 GIF 覆盖层 |
| `intro-gif-finished` | `index-intro-gif.js`（播完 / 跳过） | 解锁滚动、导航栏淡入、移除覆盖层 |

同步脚本放在 `<head>` 是为了在 `<body>` 渲染前完成隐藏，避免导航栏闪现。

### 播放链路

1. 组件脚本在 `DOMContentLoaded` 启动，添加 `intro-gif-running`。
2. 第 1 帧 `img.src` 赋值为 `overlook.GIF`，等待 `load` 后开始计时 9300ms。
3. 第 1 帧开播后再用 `new Image()` 预取下一帧，避免与本帧争抢带宽；
   切帧时才把 `src` 赋给 `<img>`，使 GIF 从第 1 帧开始播放（预取只进 HTTP 缓存）。
4. 第 2 帧 `up.GIF` 播 8500ms 后收尾：覆盖层淡出、导航栏淡入、解除滚动锁定、释放 `src`。

播放顺序由 `src/index.njk` 中两个 `.intro-gif__frame` 的 DOM 顺序决定，调整顺序只需交换这两个节点（连同各自的 `data-duration`）。

### 写入入口与受影响模块

| 写入入口 | 读取方 / 刷新路径 | 风险控制 |
|---|---|---|
| `src/index.njk`（模块 0 标记 + front matter `js`） | `npm run build` 生成根目录 `index.html` | 标记默认 `display:none`，未激活既不渲染也不下载 GIF |
| `src/_includes/head-extra/index.njk`（组件 CSS + 同步 arm 脚本） | 仅 index 页 `<head>` 末尾（在 `mobile.css` 之后） | 仅在 `prefers-reduced-motion` 未开启时 arm |
| `static/css/components/index-intro-gif.css` | 仅 index 页加载 | 配色/间距/圆角/阴影/时长/缓动全部取设计令牌 |
| `static/js/components/index-intro-gif.js` | 仅 index 页 `defer` 加载 | IIFE 封装，仅依赖 `iGEMUtils` |

## 失败与回滚边界（关键）

任何一条链路失效都必须保证导航栏能显示，绝不允许首页被永久锁死：

| 场景 | 行为 |
|---|---|
| JS 被禁用 | 覆盖层保持 `display:none`，GIF 不下载，导航栏正常显示 |
| `prefers-reduced-motion: reduce` | 不 arm、不播放、不下载，导航栏直接显示 |
| 组件脚本 404 / 执行报错 | `<head>` 内 6s 看门狗强制添加 `intro-gif-finished`，恢复导航与滚动 |
| 单张 GIF 404 / 下载超 20s | 跳过该帧进入下一帧，不阻塞 |
| 用户主动跳过 | 点击按钮或按 Esc 立即收尾 |

## 未实施

- 不对 GIF 做转码、压缩或分辨率提升（两张共约 24MB，全屏 `object-fit: cover` 会放大 712×400 素材，清晰度受素材限制；如需改善需重新导出更高分辨率素材或转 WebP/视频）。
- 不做「整个会话只播一次」的 `sessionStorage` 记忆（当前每次进入首页都会播放；如需只播一次可另行确认）。
- 不同步至 `igem2026-flask/`（两工程边界互不跨越，需另行提出）。

## 验收标准

1. `node --check static/js/components/index-intro-gif.js` 通过。
2. `npm run build` 成功，`index.html` 含组件 CSS、组件 JS 与模块 0 标记。
3. HTTP 下首页：覆盖层占满视口，播放期 `nav` 为 `visibility:hidden`、滚动锁定。
4. 两张 GIF 依次播放（`overlook.GIF` → `up.GIF`），切帧约在 9.3s、总时长约 17.4s，与素材时长一致。
5. 自动播完或点击跳过 / 按 Esc 后：覆盖层隐藏、导航栏可见、滚动解锁、`img` 的 `src` 被释放。
6. `prefers-reduced-motion: reduce` 下不播放、导航栏直接可见。
7. 「跳过动画」按钮为无边框、无背景的纯文字按钮。
8. 无控制台报错。
