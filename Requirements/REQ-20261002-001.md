## 1. 需求（用户原话 + 契约）

> "右边的项目原理示意图是从左边酵母卡通形象放大而来，类似于那种想法泵出的感觉，以酵母头部中心为图片的最小值点，然后沿着轨迹往右上移动到当前原来页面的位置，过程中图片逐渐变大。记得做移动端的校验。"

**契约（默认项，全部有调参入口）**：

| 项 | 内容 |
|---|---|
| 区块 / 元素 | `#dbtl-cycle` 屏；动元素 `.art--dbtl-cycle-diagram`，起点锚 `.art--dbtl-cycle-mascot` |
| 初始态 | 示意图不可见，中心锚定吉祥物头部中心（素材比例 0.49/0.36），scale 0.05 |
| 触发 | 首次滑入本屏（IO threshold 0.45）；**每次加载只播一次**，滑走滑回不重播 |
| 运动 | 先在头部快速浮现（0.05→0.08，14% 处不透明度到 1）→ 沿主轨迹 42% 处向上弓起 6% 舞台高（泵出感）→ 飞到现有位置，scale 0.32 → 1 |
| 结束态 | 与 `index.css` 现有布局逐像素一致（transform 清空交回 CSS） |
| 降级 | 无 JS / `prefers-reduced-motion` / 无 IO / 无 WAAPI → 完整静态布局（隐藏类只由 JS 加） |
| 明确不做 | 不加火花/灯泡特效；不改任何最终布局数值 |

## 2. 写入入口（唯一）

| 内容 | 位置 |
|---|---|
| 挂脚本 | `src/index.njk` front-matter `js:` 追加 `static/js/pages/dbtl-pump.js`；示意图处补注释 |
| 动画逻辑 | `static/js/pages/dbtl-pump.js`（**新建**：armed → IO → 量测 → WAAPI 泵出 → 同帧收尾） |
| 隐藏态样式 | `static/css/index.css` dbtl-cycle 段后新增 `.js-pump-armed .art--dbtl-cycle-diagram { opacity:0; z-index:4; will-change }` |
| 屏位数值 | 未改动（diagram 桌面 46.7%/13.2%/48.5%，移动 6%/18%/88% 仍是唯一事实源） |

**关键实现点**：
- 动画期间示意图 `z-index: 4`：DOM 里吉祥物在其后（默认绘制在上），不抬层小图会藏在头部后面而非"从头部泵出"；收尾随类还原。
- 轨迹中段控制点 = 主轨迹 42% 处再上弓 6% 舞台高；`fill: 'both'`（pitfalls A1 教训：backwards 会"到位后闪没"）。
- 收尾（去类 + 清内联 transform + cancel 动画）同一帧完成，末帧 == CSS 默认态。
- 量测在 IO 回调内 + 尺寸校验 + 逐帧重试 30 帧（`img { content-visibility: auto }` 视口外 0 高坑）。
- `done` 标志防重复；resize 在播放完成前重新量测并复位隐藏态。

## 4. 可调参数（`static/js/pages/dbtl-pump.js` 顶部常量块）
