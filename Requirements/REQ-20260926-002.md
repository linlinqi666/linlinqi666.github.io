## 一、拆分依据（他队样本）

样本来源：`static/expriments/The extreme/` 三套页面资料包（experiments 三队、results 六队、contribution 六队），并对其中可访问的 2025 wiki 实际渲染复核。

| 队伍 | Experiments 页 | 协议类内容位置 | 设计类内容位置 |
|---|---|---|---|
| Heidelberg | 即完整协议手册，按技能分类，每卡四段（简介 / Materials / Step by Step / Notes） | 同页 | —（未单独分页） |
| McGill | 周记式记录，反例（无法按实验检索） | 无独立协议 | — |
| EPFL | 模块概览 + 图片 + 折叠协议条目 | **独立 Protocols 页**：H1 Laboratory Protocols，按技术类别分 6 组，每条协议一卡（编号 + 名称 + 一句话 + 细节入口） | **独立 Design 页**：Overview → 各设计模块 → 设计依据 |
| NUDT-China | Molecular / Cell Experiments 两节 | 无独立协议页 | **独立 Design 页**：Overview → System Architecture → 各模块设计 → 优势 → 扩展 |
| SZU-China | `Experiments`（概览）+ `Protocol`（同页大区块）两个 H1；协议区按五组操作类别，长步骤收进折叠盒 | 同页 Protocol 区 | **独立 Design 页**：背景 → 框架 → Design Part 1–4（含多代方案迭代）→ 模块整合 |
| Tsinghua | 5 个实验模块，无独立协议页 | — | 无 design 页（用 engineering） |

官方口径：2025 官方 example wiki 只有 `experiments` 页（要求覆盖分步流程与参数、目的与设计、排错经验三段），没有 `protocols` 页与 `design` 页。拆成 Design + Protocol 属队伍自定义组织，官方三段要求由两页共同覆盖。

**结论（用于本次拆分）**：

1. 协议内容独立成块或成页是常见做法（EPFL 独立页、SZU 同页大区块、Heidelberg 同页手册）。
2. 协议条目通用写法：按模块或操作类别分组；每条协议固定结构（名称 + 目的 + 材料 + 步骤）；长内容用折叠或分卡承接。
3. 设计页通用写法：背景与动机 → 系统/实验总体框架 → 各模块设计（设计什么、为什么）→ 方案迭代 → 小结。
4. 我方取舍：协议页按四个实验模块分组（与现有页面结构一致，不另起技术分类）；设计页保留现有设计叙事并按模块展开，方案迭代单独成节。
