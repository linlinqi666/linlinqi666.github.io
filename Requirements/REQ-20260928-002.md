## 3. 关键诊断

- **「粒子抽搐」根因**：全仓无 canvas 粒子库，首页脚本仅 `PageProgressBar`。抽搐来自首页 CSS 星点/吉祥物（`floatYeastSoft`）在触屏上多元素同时无限动画 + `will-change` 多合成层 → 掉帧抖动。已通过 `pointer: coarse` / `max-width: 768px` **停用装饰浮动**（仅保留 hero 入场）解决。
- **拥挤/重叠根因**：`.art--s*-mascot` 等绝对定位装饰为桌面构图。C 以 `transform: scale()` 缩放吉祥物 `0.62`、小装饰 `0.5` 并降透明度缓解（`.art` 基础规则无 transform，不与桌面冲突）。

## 15. 2026-09-28 追加 8：把首页修复提炼为全局方案 + 其他页面同步（用户要求）

**架构事实**（README §二/§〇-1）：`index.css`=全局基础、`mobile.css` 必须最后加载=响应式唯一事实源、`navigation.css` 含冻结的 `:root` 令牌；所有页面经 `base.njk` 共用 `footer.njk`/`nav.njk`。

**全局方案（替代分散在 index.css 的 per-page hack）**：
1. 在 `mobile.css`（最后加载层）把 `.home-page .art-stage img` 例外块扩展为 `background-color/border-radius/max-width:none`，并**集中**加 `.home-page .art-stage--s3 .s3-pill img { height: var(--s3-pill-h); max-width:none }`——对所有页面统一生效。
2. 从 `index.css` 删除重复的 `.s3-pill img` 高度 hack，仅保留 `.s3-pills` 盒子的竖屏位置/高度变量（布局属 index.css 职责）。

**同步结论**：
- 内容条（`.art-stage`）布局**仅 `src/index.njk` 使用**（全仓 grep 唯一），无其他页面需改同一套拼装插画；其高度保护现已全局化。
- 页脚 logo 条带修复落在 `navigation.css`，因 `footer.njk` 经 `base.njk` 全站共用，**自动同步 18 个页面**；已在 `project/description.html`（非首页）实测 320px 下卡片满宽、logo 完整。
- 其他页面的移动端布局在其各自页级 CSS（description.css/design.css/members.css 等），本次未触碰，无需同步。

**验证**：390px 首页 pill 高度 16px/maxW none；320px description.html 页脚 maxW 100%、flex 0 0 auto、卡片 208px。

## 19. 2026-10-02 追加 12：WHY EHCO Yeast? 屏滚动卡顿 + 内容条右缘不渐隐（用户报障）

**现象（用户）**：该屏「卡顿非常严重」；中间一排右侧的条带「直接出现而不是淡出」。

**实测定位（playwright 逐帧采样 + 开关法）**：
- 静止时（含跑马灯/浮动/遮罩全开）165Hz 零丢帧 → 卡顿只发生在**滚动**时；
- 滚动期出现 67–74ms 单帧卡顿；**去掉 `.intro-pills` 的 `mask-image` → 14ms（卡顿消失）；只停跑马灯 → 卡顿仍在** → 元凶 = 容器级遮罩在 root scroller 滚动时**每帧重栅格化** 1254×461 的遮罩区域；
- 用户端「右缘直接出现」：`mask` 挂在**含合成子层（跑马灯轨道做 transform 动画）的外盒**上时，遮罩对合成子层的应用依赖 GPU 路径，不稳定——表现为一侧渐隐失效（用户截图：左侧淡、右侧不淡；我方 Chromium 曾两个边缘都正常，正是"不同机器不同渲染路径"的证据）。

**修复**（`static/css/index.css` 的 `.intro-pills__row`，2026-10-02）：
1. 双侧渐隐遮罩从 `.intro-pills` 外盒**下沉到每排** `.intro-pills__row`（排自身即遮罩面，不再依赖"父遮罩罩合成子层"）；
2. 排加 `transform: translateZ(0)` 提升合成层 → 滚动只是平移已栅格化图层，不再每帧重栅格化；
3. 参数不变（`--intro-fade` / `--intro-flow-dur` 仍在外盒可调）。

**验证**：40% 渐隐探针证实遮罩几何正确（实心区 502–752px 与理论一致，合成层未拉伸遮变）；热身 A/B/C/D 滚动帧率采样全零丢帧（本机 A 修复方案 max 13ms vs D 原方案 max 20ms——本机 GPU 强，差距在小数值；**重栅格化成本在大 GPU 压力下按面积放大**，弱 GPU/高分屏收益为主）；1280/1080/390 三档左右缘截图渐隐正常。证据：`对话归档/screenshots/2026-10-02-intro-*.png`（9 张）。

**待用户复验**：Ctrl+F5 后滚到该屏看卡顿与右缘渐隐；若仍卡，下一候选是全局 `img { content-visibility: auto }`（滚动进屏时的解码/布局尖峰）与 `floatYeastSoft` 多层合成，逐项开关定位。
